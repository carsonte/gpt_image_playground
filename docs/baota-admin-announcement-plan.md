# 宝塔生产部署与运营后台规划

## 1. 文档状态

- 版本：v0.1
- 状态：需求已确认，待开发
- 目标域名：`https://img2.blackengine.top`
- 上游图片 API：`https://api.blackengine.top/v1`
- 默认模型：`gpt-image-2`
- 部署环境：宝塔面板、Nginx 1.28.1、Docker

## 2. 项目目标

在保留现有图片生成体验和浏览器本地数据存储方式的基础上，增加一套适合单站点运营的轻量服务端，解决以下问题：

1. 将上游 API URL 和 API Key 固定在服务器端，前端不能查看或修改真实配置。
2. 提供公告管理后台，支持弹窗和置顶悬浮横条等展示方式。
3. 提供访问量、图片生成量、尺寸趋势和提示词审计，但不收集参考图或生成图片。
4. 提供可检索的运营与系统日志，方便定位故障和审计后台操作。
5. 使用 Docker 部署到宝塔，通过宝塔 Nginx 绑定域名和 HTTPS。

## 3. 范围

### 3.1 本期功能

- 单管理员登录。
- 公告新增、编辑、删除、发布、下线和重新推送。
- 公告弹窗、仅弹一次、置顶悬浮横条、允许关闭。
- 公告定时生效和自动失效。
- 独立 IP、访问次数、生图请求数、图片数量、成功率、请求尺寸和每日趋势统计。
- 生成记录中查看真实 IP、提示词、生成/编辑动作和请求参数。
- 管理员操作、图片请求、系统错误和安全事件日志。
- 服务端 API 代理和服务器端 API Key 注入。
- 宝塔 Docker Compose、Nginx 反向代理和 HTTPS 部署。

### 3.2 暂不包含

- 用户注册、登录和会员系统。
- 套餐、充值、计费或个人额度。
- 服务端图片画廊。
- 服务端保存参考图或生成图片。
- 多管理员、角色和复杂权限系统。

## 4. 核心原则

### 4.1 图片仍由用户本地保存

现有任务、提示词、参考图和生成图片继续存放在用户浏览器的 IndexedDB。服务端额外保存最长 90 天的提示词审计记录，但不增加图片存储，也不把参考图或生成结果复制到服务器。

清理浏览器数据、更换设备或使用无痕模式后，本地历史记录可能丢失；这属于现有产品行为，不在本期增加云端同步。

### 4.2 API Key 不能进入前端

真实 API Key 只保存在服务器环境变量或 Docker Secret 中。禁止把真实 Key 放入以下位置：

- `VITE_*` 环境变量。
- 前端预置 JSON。
- URL 查询参数。
- JavaScript 构建产物。
- Git 仓库和 Docker Compose 明文文件。

浏览器统一请求本站同源 `/api-proxy/`。服务端代理转发到 BlackEngine 时添加真实 `Authorization` 请求头。

### 4.3 内容审计边界

生成记录保存提示词、真实 IP 和必要请求参数，仅管理员可访问。通用日志仍不记录提示词。所有服务端模块均不记录以下内容：

- API Key。
- 完整上游响应正文。
- 参考图片、蒙版和生成图片。
- 上游返回的图片 URL。

## 5. 总体架构

```text
浏览器
  ├─ 静态前端与本地 IndexedDB
  ├─ GET /api/announcements
  ├─ POST /api/visits
  └─ POST /api-proxy/images/*
           │
           ▼
宝塔 Nginx（域名、HTTPS、限流）
           │
           ▼
应用服务
  ├─ 静态文件
  ├─ 公告 API 与管理后台
  ├─ 匿名统计
  ├─ API 代理与服务端 Key 注入
  └─ 持久化数据卷
           │
           ▼
https://api.blackengine.top/v1
```

生产环境优先采用一个应用镜像和一个持久化数据卷，减少宝塔维护成本。宝塔 Nginx 只负责入口 HTTPS、域名转发、访问限制和基础限流。

## 6. 前台公告体验

### 6.1 公告展示类型

一条公告可以同时启用多个展示渠道：

- 弹窗：用户进入网站后展示模态弹窗。
- 置顶悬浮横条：置顶消息与悬浮横条共用同一个展示位和同一份内容，固定在页面顶部，可选跳转链接。

### 6.2 仅弹一次

浏览器使用公告 `id + version` 记录已展示状态：

```text
announcement:{id}:{version}:popup-seen
```

- 开启“仅弹一次”后，同一浏览器只弹一次。
- 普通内容编辑不强制打扰已经看过的用户。
- 管理员执行“重新推送”时增加 `version`，所有用户会再次看到。
- 清理浏览器数据或更换浏览器后会被视为新用户。

### 6.3 横条关闭

允许关闭的悬浮横条使用同样的 `id + version` 记录关闭状态：

```text
announcement:{id}:{version}:bar-dismissed
```

重新推送后旧关闭记录自动失效，横条再次出现。

### 6.4 展示规则

公告必须同时满足以下条件才会对外展示：

- 状态为“已发布”。
- 当前时间不早于开始时间。
- 当前时间不晚于结束时间，或未设置结束时间。
- 至少启用一种展示渠道。

多条公告同时生效时，按“优先级、发布时间”排序。弹窗默认每次页面加载最多展示一条，避免连续弹窗。

## 7. 管理后台

### 7.1 地址与认证

- 后台地址：`https://img2.blackengine.top/admin`
- 本期采用单管理员账号。
- 管理员密码以强哈希形式保存，不保存明文。
- 登录成功后使用 `HttpOnly`、`Secure`、`SameSite=Strict` Cookie。
- 登录接口增加失败次数限制和短时封禁。

管理员账号、密码哈希、会话密钥和统计哈希密钥均通过服务器环境变量提供。

### 7.2 公告管理字段

| 字段 | 说明 |
|------|------|
| 标题 | 公告标题 |
| 正文 | 支持安全 Markdown 子集或纯文本 |
| 链接 | 可选跳转地址和按钮文字 |
| 状态 | 草稿、已发布、已下线 |
| 展示渠道 | 弹窗、置顶悬浮横条，可多选 |
| 仅弹一次 | 仅控制弹窗渠道 |
| 允许关闭 | 控制弹窗或悬浮横条是否提供关闭按钮 |
| 优先级 | 数值越高越优先 |
| 开始时间 | 可选，未设置时发布后立即生效 |
| 结束时间 | 可选，未设置时持续有效 |
| 版本 | 重新推送时递增 |
| 创建/更新时间 | 服务端自动记录 |

### 7.3 后台操作

- 新建和编辑公告。
- 预览弹窗和横条效果。
- 发布、下线和删除公告。
- 重新推送公告。
- 查看当前有效公告。
- 查看统计总览和按日趋势。
- 查看、筛选和导出脱敏日志。

删除属于不可恢复操作，后台必须二次确认。常规运营优先使用“下线”。

## 8. 统计口径

### 8.1 看板指标

- 今日、7 天、30 天和累计独立 IP 数。
- 页面访问次数。
- 生图请求次数。
- 请求生成的图片数量，按请求参数 `n` 统计。
- 成功请求数、失败请求数和成功率。
- 按日访问趋势和生图趋势。
- 最近 30 天热门提示词关键词、使用次数和请求覆盖率。

### 8.2 访问次数

- 前端页面加载后调用一次访问接口。
- 同一 IP 在 30 分钟内重复访问只计一次访问会话。
- 独立 IP 按统计周期去重。
- 不使用浏览器指纹。

### 8.3 真实 IP 与拉黑

服务端通过可信反向代理头获取客户端真实 IP。真实 IP 仅保存在访问和生图活动表中，供管理员排查滥用和执行精确拉黑，默认保留 90 天。服务器同时保存不可逆摘要：

```text
HMAC-SHA256(STATS_HASH_SECRET, normalizedIp)
```

统计哈希密钥只存在服务器环境变量中。通用日志只输出摘要，不输出真实 IP 或完整请求头；真实 IP 只在受管理员会话保护的“IP 管理”页面展示。

管理员可按真实 IP 查看访问次数、生图请求、图片数量、成功/失败及最后活动时间，并添加或解除精确 IP 拉黑。被拉黑的 IP 在请求上游 API 前即被拒绝，不消耗上游额度。

### 8.4 生图数量

服务端代理在请求发往上游前记录一条“请求开始”，从请求体提取 `n`，缺省按 1 计算。上游成功返回后标记成功，网络错误或非成功状态标记失败。

本期统计的是上游请求和预期图片数量，不对生成图片内容做解析或持久化。

## 9. 日志中心

### 9.1 日志类型

- 管理操作日志：登录、退出、公告新增、编辑、发布、下线、重新推送和删除。
- 图片请求日志：请求时间、IP 摘要、接口类型、模型、请求图片数量、状态、耗时和上游状态码。
- 系统错误日志：服务启动失败、数据库异常、上游网络错误和定时任务错误。
- 安全事件日志：登录失败、触发限流、非法代理路径、无效会话和 CSRF 校验失败。

### 9.2 日志字段

统一日志至少包含：

| 字段 | 说明 |
|------|------|
| 时间 | 服务端 UTC 时间，后台按本地时区展示 |
| 级别 | `info`、`warn`、`error` |
| 类型 | 管理操作、图片请求、系统错误、安全事件 |
| 事件 | 稳定的事件名称，如 `announcement.publish` |
| 请求 ID | 用于关联一次请求的前后日志 |
| IP 摘要 | 使用 HMAC 摘要；真实 IP 仅在 IP 活动表中保存和展示 |
| 状态 | 成功、失败或被拒绝 |
| 耗时 | 请求处理耗时，单位毫秒 |
| 详情 | 经过白名单过滤的结构化信息 |

### 9.3 脱敏规则

日志禁止保存：

- API Key、Authorization、Cookie 和管理员密码。
- 用户提示词、参考图、蒙版和生成图片。
- 完整请求体、完整上游响应和图片 URL。
- 通用日志中的原始 IP 地址。

错误信息写入前需要清除疑似密钥、认证头、查询参数和上游响应中的敏感字段。对外展示的错误堆栈仅管理员可见，前台只返回简化错误和请求 ID。

### 9.4 后台能力

- 按时间、级别、类型、状态和请求 ID 筛选。
- 查看请求耗时、上游状态码和脱敏错误摘要。
- 查看单个事件详情和同请求 ID 的关联日志。
- 导出筛选结果为 CSV，不允许导出敏感字段。
- 默认仅允许清理过期日志，不提供随意修改日志的能力。

### 9.5 保留策略

- 图片请求与系统日志默认保留 30 天。
- 安全事件和管理员操作日志默认保留 180 天。
- 每日定时清理过期记录，并记录清理结果。
- Docker 标准输出日志启用轮转，避免占满服务器磁盘。
- 保留天数和单文件大小通过服务器环境变量配置。

## 10. 服务端 API 初稿

### 9.1 公共接口

```text
GET  /api/announcements
POST /api/visits
POST /api-proxy/images/generations
POST /api-proxy/images/edits
POST /api-proxy/responses
```

代理只允许项目实际使用的路径和 HTTP 方法，禁止做成可转发任意 URL 的开放代理。

### 9.2 管理接口

```text
POST   /api/admin/login
POST   /api/admin/logout
GET    /api/admin/session
GET    /api/admin/announcements
POST   /api/admin/announcements
PUT    /api/admin/announcements/:id
POST   /api/admin/announcements/:id/publish
POST   /api/admin/announcements/:id/unpublish
POST   /api/admin/announcements/:id/republish
DELETE /api/admin/announcements/:id
GET    /api/admin/stats/summary
GET    /api/admin/stats/trends
GET    /api/admin/logs
GET    /api/admin/logs/:id
GET    /api/admin/logs/export
```

所有 `/api/admin/*` 接口除登录外必须校验管理员会话，并对修改操作验证 CSRF 防护。

## 11. 数据持久化

本期数据量较小，优先使用 SQLite，数据库文件放入 Docker 持久化卷：

```text
/app/data/app.db
```

核心表：

- `announcements`：公告内容、展示规则、版本和状态。
- `admin_sessions`：管理员会话摘要和过期时间。
- `visit_sessions`：匿名 IP、会话窗口和访问时间。
- `generation_events`：日期、数量、成功状态和耗时，不含内容数据。
- `daily_metrics`：按日聚合结果，减少后台查询成本。
- `audit_logs`：管理员操作和安全事件。
- `request_logs`：脱敏的图片请求、系统错误和请求关联信息。

数据库需要每日自动备份，保留最近 7 份。更新容器时不得删除数据卷。

## 12. 安全要求

- 全站强制 HTTPS。
- 真实 API Key、管理员密码和会话密钥不得提交到 Git。
- 管理后台限制登录尝试次数。
- API 代理限制来源域名、路径、请求体大小、并发和速率。
- 不信任客户端传入的转发目标、Authorization 和统计数量。
- 服务端覆盖客户端 Authorization，不把真实 Key 返回给浏览器。
- 公告正文需要防止 XSS，链接只允许 `https` 或站内相对地址。
- 管理接口记录必要审计事件，但不记录密码、Key 和会话 Cookie。
- 所有日志写入前执行字段白名单和敏感信息脱敏。
- 宝塔面板端口不应长期对全网开放，建议配置安全入口或 IP 白名单。

建议初始限流：

- 普通页面和公告接口：每 IP 每分钟 120 次。
- 生图接口：当前默认每 IP 同时 1 个请求、最多排队 3 个，后台可调整；超额返回 HTTP 429。
- 管理员登录：每 IP 每 15 分钟 10 次失败尝试。

限流值应通过服务器环境变量调整。

## 13. 宝塔部署方案

### 12.1 DNS 与证书

1. 将 `img2.blackengine.top` 的 A 记录指向服务器公网 IP。
2. 在宝塔创建站点 `img2.blackengine.top`。
3. 申请并启用 Let's Encrypt 证书。
4. 开启 HTTP 自动跳转 HTTPS。

### 12.2 Docker

通过宝塔“Docker → 容器编排”部署项目。应用容器只绑定本机端口：

```text
127.0.0.1:8080 -> container:8080
```

宝塔 Nginx 将域名反向代理到 `http://127.0.0.1:8080`。外部不直接开放应用容器端口。

### 12.3 服务器环境变量

计划使用以下变量，具体名称在实现阶段保持向后兼容：

```dotenv
UPSTREAM_API_URL=https://api.blackengine.top/v1
UPSTREAM_API_KEY=<服务器密钥>
DEFAULT_IMAGE_MODEL=gpt-image-2
ADMIN_USERNAME=admin
ADMIN_PASSWORD_HASH=<强哈希>
SESSION_SECRET=<随机密钥>
STATS_HASH_SECRET=<随机密钥>
DATA_DIR=/app/data
TRUST_PROXY=1
REQUEST_LOG_RETENTION_DAYS=30
AUDIT_LOG_RETENTION_DAYS=180
```

真实值只写入服务器受限文件或宝塔容器环境变量，不写入仓库中的示例文件。

## 15. 验收标准

### API 与隐私

- 浏览器开发者工具中无法读取真实 BlackEngine API Key。
- 修改客户端 Authorization 不能覆盖服务器端 Key。
- 服务端生成记录可查看提示词，但数据库中不存在参考图或生成图片内容。
- 生成图片仍只出现在用户浏览器本地数据中。

### 公告

- 后台可创建、编辑、发布、下线和删除公告。
- 弹窗“仅弹一次”按公告版本正确生效。
- 重新推送后已看过的用户能再次看到。
- 悬浮横条可关闭，关闭状态按版本保存。
- 置顶悬浮横条、优先级和起止时间规则正确。

### 统计

- 30 分钟访问会话去重正确。
- 独立 IP 使用匿名哈希去重。
- 生图请求数、图片数量和成功失败状态可核对。
- 后台可查看今日、7 天、30 天和累计数据。

### 日志

- 后台可按类型、级别、状态、时间和请求 ID 检索日志。
- 生图失败可通过请求 ID 定位到脱敏的上游状态和错误摘要。
- 公告发布、下线、重新推送和删除均有审计记录。
- 日志和导出文件中不存在 Key、Authorization、Cookie、提示词或图片内容；真实 IP 只在受保护的 IP 管理页面显示。
- 过期日志会自动清理，Docker 日志轮转不会无限占用磁盘。

### 部署

- `https://img2.blackengine.top` 可正常访问并强制 HTTPS。
- 容器重启和更新后公告、统计数据不丢失。
- 宝塔外部只开放 80、443 和受保护的面板入口。
- 数据库备份可恢复。

## 16. 实施前确认项

以下项目在正式部署前确认，不阻塞本地开发：

- 域名 DNS 是否已经指向目标服务器。
